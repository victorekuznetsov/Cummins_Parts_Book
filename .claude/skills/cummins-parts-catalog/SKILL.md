# Каталог запчастей Cummins по ESN

Порядок жёсткий: **сначала выгрузить всё с сайта и залить на GitHub, потом
собирать каталог**. Не собирайте каталог из неполной выгрузки — сверка полноты
делается по сырым данным.

## Подготовка

```
pip install playwright requests openpyxl
playwright install chromium
```

Учётная запись на parts.cummins.com **не нужна**: сайт отдаёт каталог анонимной
сессии (пользователь `PUBLIC`).

Готовые скрипты лежат в `github.com/victorekuznetsov/Cummins_Parts_Book`
(`crawler.py`, `crawl_details.py`, `tools/`). Если работаете в другом
репозитории — скопируйте их оттуда, не переписывайте с нуля.

---

## Шаг 0. Сколько каталогов вообще нужно

Каталог определяется **CPL**, а не серийным номером. У парка одинаковых машин
CPL, как правило, один — тогда достаточно одного каталога.

```
python tools/check_esn.py esn_list.txt      # список ESN, лишняя разметка игнорируется
```

Скрипт печатает по каждому ESN модель, CPL, конфигурацию, дату сборки и
группирует по CPL; в `esn_report.json` кладёт представителя каждой группы.
46 номеров проверяются примерно за минуту.

**Качайте по одному ESN на CPL — самый свежий по дате сборки.** Внутри одного
CPL состав всё же слегка плавает по годам выпуска (на реальном парке NTE200
между 2022 и 2025 годом добавилось 45 номеров и убрано 54). Покажите это
пользователю:

```
python tools/diff_esn.py <ESN1> <ESN2> ...   # что добавлено/убрано между сборками
```

## Шаг 1. Выгрузка (и сразу на GitHub)

```
python crawler.py <ESN>                      # паспорт, узлы, спецификации, чертежи
python crawl_details.py <ESN> --workers 8    # карточки деталей и все ракурсы фото
```

Замеры: двигатель на 1128 деталей — 3,5 мин структура + 11 мин карточки,
около 105 деталей/мин, ~250 МБ. Повторный запуск дозагружает недостающее.

Результат в `data/<ESN>/`: `engine.json`, `options/*.json`, `partdetails/*.json`,
`kitSets.json`, `drawings/`, `parts/`, `report.json`.

**Проверьте `report.json`: `parts_lost` должен быть пуст.** Если нет —
разбирайтесь с выгрузкой, каталог не собирайте.

Залейте выгрузку до сборки каталога:

```
git add -A && git commit -m "Выгрузка Cummins <модель> ESN <ESN>" && git push
```

В `.gitignore` обязательно: `session/` (там куки и токены — наружу их нельзя),
`*.log`, `*.part`. Картинки из `data/<ESN>/drawings` и `data/<ESN>/parts` тоже
исключите: те же файлы копируются в `catalog/`, дублировать 200+ МБ незачем.

## Шаг 2. Сборка каталога

```
python tools/build_catalog.py <ESN> --machine <машина> --fleet-from esn_report.json
```

Создаёт `catalog/data/<ESN>.js`, копирует чертежи и фото в `catalog/drawings/<ESN>/`
и `catalog/parts/<ESN>/`, дописывает двигатель в переключатель `catalog/engines.js`.
Оболочка (`index.html`, `app.js`, `styles.css`) статическая — её не трогать.

`--machine` — машина, на которой стоит двигатель (NTE200, SD90C-5): она
показывается в переключателе и попадает в выгрузку заказа.

## Шаг 3. Проверка и заливка

```
python tools/verify_catalog.py
```

Открывает каталог в настоящем браузере по `file://` и проверяет: позиция 1 есть
в каждой системе, чертежи и фото грузятся, работает поиск по номеру и по
заменённому номеру, открывается карточка детали, считается и сохраняется заказ,
в консоли нет ошибок. **Все пункты должны быть зелёными.** Затем коммит и push.

## API parts.cummins.com

База: `https://parts.cummins.com/gateway/api/IACDataServices`

| Запрос | Что отдаёт |
|---|---|
| `/v2/esnInfo/{ESN}?esnType=mbom` | паспорт (модель, CPL, конфигурация, дата) и весь состав: узлы, детали, системы |
| `/v2/componentDetails/option?esnType=mbom&componentHash=…&esn=…` | спецификация узла: `callOut` (номер позиции), количество, типоразмер, `graphics[]` |
| `/protected/partDetails?partNo=…&smn=` | карточка детали: `metadata` (масса, габариты, опасный груз), `supersession`, `whereUsed`, до 7 ракурсов фото, 3D `.obj/.mtl` |
| `/v2/esnInfo/{ESN}/gasketSets`, `POST /v2/esnInfo/{ESN}/kitSets` | комплекты прокладок и ремкомплекты (в kitSets телом идёт список `componentHash`) |
| `/graphics/rtgraphics/english/parts{fileName}.png` | чертёж узла (`fileName` из `graphics[]`) |
| `/graphics/parts/{первые 3 цифры}/{номер}/{номер}_iso.png` | фото детали |
| `/graphics/engines/{Система}.png` | картинка системы и общий вид двигателя |

### Авторизация

1. Playwright открывает `https://parts.cummins.com/home` — сайт сам берёт
   анонимную сессию через `GET /gateway/auth/login/publicUser`.
2. Забрать куки из контекста; **обязателен заголовок `x-xsrf-token` со значением
   куки `XSRF-TOKEN`** — без него шлюз отвечает `403` даже с правильными куками.
3. Дальше и JSON, и картинки прекрасно качаются обычным `requests` с этими
   куками — за счёт этого выгрузка распараллеливается в 8 потоков и идёт в
   десятки раз быстрее, чем через `page.evaluate`.

**Не заходить в карточку ESN на сайте перед выгрузкой.** Для части номеров поиск
уводит на `/global-search`, а не в карточку двигателя, и попытка дождаться
`esn-entry` валит скрипт. Сессии с главной страницы достаточно.

Прочее: cookie-баннер OneTrust перехватывает клики — при работе через UI сначала
жать `#onetrust-accept-btn-handler`. Сайт может отвечать обрывом соединения —
во всех запросах нужны 3–4 повтора с паузой.

## Подводные камни данных (проверено, не выдумывайте заново)

- **`callOut` бывает `ASSEMBLY`** — это строка узла в сборе, а не сбой разбора.
  Показывать её как «сборка», а не как номер позиции. Проверка «первая позиция =
  1» должна это допускать.
- **У части узлов чертежа нет в источнике.** Признак — `graphicCount: "0"` и
  пустой `graphics[]`. Проверено: имя файла выводится из номера узла по формуле
  `AH5005-06 → /095/ah/095_ah0500500_06` (номер дополняется до 5 знаков + `00`),
  формула сходится на всех известных чертежах, но для этих узлов все адреса дают
  404, а на сайте вместо чертежа стоит заглушка `no-image-style` за кнопкой
  «View Graphics». Реально чертежи есть примерно у 50 узлов из 76 с позициями.
  Не выдавайте это за недоработку выгрузки — так у Cummins.
- **Замены номеров (`supersession`)** — цепочка объектов с полем `sequence`:
  **1 = действующий номер**, дальше по возрастанию — снятые с производства.
  Сортировать по убыванию `sequence`, получится «старый → новый». Поиск обязан
  находить деталь и по старому номеру, помечая в выдаче «вместо …».
- **Часть деталей отдельно не продаётся** — в карточке `sell: "kit"` (около 8–11 %
  позиций: 93 у QSK50, 96 у QST30). Такую деталь заказывают комплектом из
  `kitSets`. Обязательно показывать это в каталоге: метка в строке и блок
  «Заказывается комплектом» в карточке с кнопкой добавить комплект в заказ —
  иначе пользователь закажет то, что купить нельзя. Индекс «деталь → комплекты»
  строится из `kitSets.json`.
- **Отсутствие замен — не всегда ошибка.** Если `supersession` пуст, у Cummins
  замен по этой детали нет; прежде чем что-то чинить, проверьте живой API с
  `smn=` и без него (ответ одинаковый) — и посмотрите, не тот ли это случай, когда
  деталь просто продаётся только комплектом.
- **Наименования только на английском.** Русские названия сайт подставляет на
  клиенте из своего словаря, в API их нет. `accept-language` не помогает.
  Пользователя это устраивает — переводить не нужно.
- **Узлы без деталей** (окраска, литература, отгрузочная схема, калибровка ТНВД)
  оставлять в дереве: в них лежат примечания с полезными данными.
- Часть деталей без фото (`_iso.png` → 404) — это нормально, около 20 %.

## Каким должен быть каталог

Требования пользователя, одинаковые для всех его каталогов:

1. Открывается **двойным щелчком по `index.html`, без сервера**. Значит все
   данные — в `.js` (`window.CATALOGS[...]`), а не в `.json`: `file://` блокирует
   `fetch` локальных файлов.
2. **Чертёж рядом со списком позиций**, номер на чертеже = номер позиции;
   у многолистовых узлов — карусель, щелчок увеличивает.
3. Колонки таблицы: № · номер детали · наименование · цена · кол-во на схеме ·
   «Нужно» · «＋ в заказ».
4. **Карточка детали** по щелчку на номере: все ракурсы фото, масса и габариты в
   кг и мм (в источнике фунты и дюймы — пересчитывать), «продаётся отдельно»,
   класс опасного груза, где применяется, цепочка замен номера.
5. **Корзина заказа:** редактирование количества, серийный номер машины, сумма,
   выгрузка в CSV (разделитель `;`, BOM — чтобы Excel открыл сразу) и печать,
   сохранение в браузере.
6. **Поиск** по номеру, наименованию и заменённым номерам, сразу по всем
   двигателям каталога.
7. **Несколько двигателей в одном каталоге** — переключатель в шапке с
   привязкой к машине; данные и картинки раскладывать по подпапкам ESN.
8. Оформление светлое; вверху строка контактов: «По вопросам работы каталога
   запасных частей, ошибок, замечаний обращаться к Кузнецову В.Е.
   KuznetsovVE@industrservice.ru».
9. Скрипты пересборки — в `tools/`, чтобы каталог собирался из выгрузки заново.

## Что доложить пользователю

Модель, CPL, конфигурацию и дату сборки; систем / узлов / позиций / уникальных
деталей / чертежей / фото / деталей с заменой номера; **явно — что потеряно 0
номеров**; сколько узлов без чертежа и почему; ссылку на репозиторий.
Отдельно предупредить, если внутри одного CPL состав различается по годам.
