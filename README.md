# Каталог запасных частей Cummins — публикуемая версия (GitHub Pages)

Статический онлайн-каталог запчастей двигателей Cummins, собранный из
официального каталога **parts.cummins.com** по серийным номерам (ESN).
Оформление — фирменный стиль «Развитие», светлая и тёмная тема.

Это **ветка `gh-pages`** — сборка для публикации на GitHub Pages: страница
каталога, данные всех 40 двигателей, чертежи узлов и **локальные фото
деталей для всех двигателей** (`parts/<ESN>/`). Не входят только самые
тяжёлые исходники, которые каталогу не нужны напрямую: сырая выгрузка EPC
(`rawdata/`), документы QuickServe (`bulletins/`) и хранилище Obsidian
(`obsidian-vault/`) — вместо них база знаний и недостающие иллюстрации
ссылаются на QuickServe. Сайт статический и полностью открытый: логина на
этой ветке нет (GitHub Pages не выполняет серверный код, поэтому серверная
проверка входа, которая используется в деплое на Vercel, здесь недоступна —
см. «Доступ» ниже).

Полная версия каталога со всеми данными, базой знаний и исходной выгрузкой
(`rawdata/`, `crawler.py`, `crawl_details.py`, `tools/`, брендбук) — в ветке
**`claude/cummins-catalog-nhl-improvements-9e7gto`**; закрытый логином
деплой на Vercel собирается из ветки **`deploy-vercel`**. Ветка `main`
используется отдельно для сырой выгрузки QuickServe и в публикацию не
входит.

По вопросам работы каталога, ошибок и замечаний — Кузнецов В.Е.,
KuznetsovVE@industrservice.ru

## Что внутри

```
index.html · app.js · styles.css   оболочка каталога (статическая)
engines.js                          список двигателей для переключателя
data/<ESN>.js                       состав каждого двигателя (window.CATALOGS)
data/prices.js                      прайс «Горная Евразия»: текущий и несогласованный
drawings/<ESN>/*.png                чертежи узлов (локально)
parts/<ESN>/*.png                   фотографии деталей (для части двигателей)
rawdata/<ESN>/                      выгрузка EPC, из неё собираются данные
build/build_catalog.py              сборка data/<ESN>.js из rawdata/
brand/                              логотипы «Развитие» (свет/тёмная тема)
```

Данные двигателей **подгружаются по требованию**: при открытии страницы
загружается только `engines.js` (список для переключателя), а `data/<ESN>.js`
— когда двигатель выбран. Поиск по всем двигателям, выгрузка «все каталоги»
и «Проверить список» перед работой догружают остальные каталоги и показывают
индикатор загрузки. Все данные вместе — это десятки мегабайт, поэтому грузить
их сразу нельзя.

Фотографии деталей на этой ветке для всех двигателей лежат локально в
`parts/<ESN>/` (поле `photos` в `data/<ESN>.js` указывает на неё). Если
локального файла всё же нет — резерв публичный CDN
`parts.cummins.com/graphics/parts/...`; если фото недоступно и там — оно
просто не показывается, остальной каталог работает.

## Возможности

- Переключатель двигателей; поиск по номеру, наименованию и заменённым
  (старым) номерам сразу по всем двигателям, а также по номерам комплектов.
- Чертёж рядом со списком позиций; карточка детали (фото, масса и габариты,
  цепочка замен номера, где применяется).
- **Комплекты (kits)** — см. раздел ниже.
- Две цены в списке позиций под общей шапкой **«Горная Евразия»**: «текущая»
  и «несогласованная» (из `data/prices.js`).
- Заказ с выгрузкой в CSV и печатью; сохраняется в браузере.
- Выгрузка всех номеров модели / всех каталогов в Excel, выгрузка комплектов
  с составом, проверка списка номеров на наличие, загрузка цен из файла.
- Светлая и тёмная тема (переключатель в шапке).

## Комплекты (kits)

Cummins поставляет часть номеров только в составе ремкомплектов. Состав
комплектов приходит в тех же данных двигателя (`kits` в `data/<ESN>.js`), и
каталог использует его так:

- В списке позиций деталь, входящая в комплект, помечена «🧰 Можно заказать
  комплектом» со ссылками на состав каждого комплекта.
- Если деталь **не продаётся отдельно** (`Sellable: N`), кнопка заказа
  заблокирована («не продаётся»), а вместо неё предлагается заказ комплектом.
  Если деталь продаётся и отдельно, и в комплекте — в строке появляется выбор
  «деталь или комплект».
- В карточке детали есть блок «Заказать комплектом» с ценами комплектов.
- Карточка комплекта показывает полный состав: номер, наименование (русское —
  из базы знаний), количество (повторы в исходных данных схлопнуты в «Кол-во»)
  и обе цены; из состава можно перейти в карточку любой детали.
- Кнопка «🧰 Все комплекты» — страница всех комплектов двигателя с ценами;
  «↓ Комплекты и состав (Excel)» — выгрузка по строке на каждую составляющую.
- Поиск и «Проверить список» находят номера комплектов, а для обычных номеров
  показывают, в какие комплекты они входят.

## Цены «Горная Евразия»

Обе цены каталога — из прайс-листов «Горной Евразии», поэтому в шапке таблицы
позиций они стоят под общим заголовком **«Горная Евразия»**, а подписи
столбцов — «текущая» и «несогласованная». Та же подпись в карточках
комплектов и в заголовках выгрузок.

`data/prices.js` — базовый прайс, который каталог показывает сразу, без
загрузки файла вручную:

- `window.CUMMINS_PRICES` — несогласованный прайс (столбец «несогласованная»),
- `window.CUMMINS_PRICES_CUR` — текущий прайс (столбец «текущая»).

Ключ — нормализованный номер детали (верхний регистр, без пробелов и дефисов).
Файл генерируется из прайс-листов ГЕ скриптом `build/gen_data.js` каталога
NHL_Parts_Book. Прайс, загруженный кнопкой «Обновить цены», сохраняется в
браузере и накладывается поверх несогласованного; столбец «текущая» он не
меняет.

## Сборка каталога из выгрузки

Сырьё EPC лежит в `rawdata/<ESN>/` (его кладут `crawler.py` и
`crawl_details.py`, порядок — в `fetch_raw.py`). Каталог собирается из него:

```
python3 build/build_catalog.py 33224404     # один двигатель
python3 build/build_catalog.py --all        # все, у кого есть rawdata/<ESN>/engine.json
python3 build/build_catalog.py --all --photos   # плюс скопировать фото в parts/<ESN>/
```

Скрипт пишет `data/<ESN>.js`, обновляет `engines.js` и копирует чертежи в
`drawings/<ESN>/`. Фотографии деталей по умолчанию **не копируются** — это
около 150 МБ на двигатель, а те же файлы уже лежат в `rawdata/<ESN>/parts/`,
откуда каталог их и берёт (поле `photos` в данных двигателя). Флаг `--photos`
вендорит их в `parts/<ESN>/`, если публикуемая ветка собирается без `rawdata/`.

Комплекты берутся из `kitSets.json` (ремкомплекты) и `gasketSets.json`
(комплекты прокладок; их номер — первая позиция состава). Цены в данные не
вшиваются: каталог берёт их из `data/prices.js` уже в браузере.

Узлы дополнительной комплектации (`upf-opt`, «Distributor Upfit») Cummins не
отдаёт через componentDetails — файла `options/<узел>.json` для них нет.
Их состав скрипт берёт из спецификации двигателя (`engine.json`) и помечает
примечанием: номера деталей на месте, но схемы и номеров позиций у таких
узлов нет и в самом EPC.

Если после этого скрипт печатает «ПОТЕРЯНО НОМЕРОВ» — выгрузка действительно
неполная, и `crawler.py <ESN>` нужно догнать на машине с доступом к
parts.cummins.com.

## Техническая документация и база знаний

Документы QuickServe лежат в `bulletins/` (HTML + PDF, реестр — `bulletins/index.json`):
**6775 документов** — процедуры ремонта, TSB, сервисные бюллетени, инструкции по
инструменту и установке, руководства. Из них собираются:

* раздел «База знаний» самого каталога — `data/kb_*.js` и `data/kb/body_*.js`;
* хранилище Obsidian в `obsidian-vault/` (документы, детали, узлы, комплекты,
  двигатели, парк, темы).

Каталог и база знаний — **только про двигатели Cummins**. Каталоги машин
(NTE200, NTE240, TR100A) живут в репозитории `NHL_Parts_Book` и сюда не
включаются.

Документация привязана к 28 двигателям каталога из 30 (нет по CPL 4342 и 8761 —
двум DH46C3). Русский текст есть у 3112 документов и русские заголовки у 5000;
остальные — по-английски: перевод делается отдельным прогоном
(`translate_docs.py`, офлайн-модель en→ru) и в готовые файлы попадает при
следующей пересборке.

### Пересборка базы знаний

```
python3 obsidian-vault/_build/build_docs.py        # HTML -> Markdown, иллюстрации из PDF
python3 obsidian-vault/_build/build_catalog.py     # детали/узлы/комплекты из data/<ESN>.js
python3 obsidian-vault/_build/build_fleet.py       # парк: машина -> VIN -> ESN -> CPL
python3 obsidian-vault/_build/write_docs.py        # заметки документов
python3 obsidian-vault/_build/write_catalog.py     # заметки каталога
python3 obsidian-vault/_build/write_fleet.py
python3 obsidian-vault/_build/write_fleet_polyus.py
python3 obsidian-vault/_build/build_index.py       # главная, индексы, темы
python3 obsidian-vault/_build/web_data.py          # data/kb_*.js для каталога
python3 obsidian-vault/_build/build_fts.py         # data/kb_fts.js — поиск по текстам
```

Поиск по текстам документов работает по индексу `data/kb_fts.js` (слово →
документы, русские и английские тексты). Он весит около 8 МБ и грузится в
браузер только при первом текстовом поиске.

Промежуточное состояние пишется в `kb_build/` (в репозиторий не попадает).
Уже переведённые документы сохраняются между пересборками: `web_data.py` берёт
их из `kb_build/_cache_ru_html/` — русский текст не теряется, даже если
`translate_docs.py` не запускался. Новую выгрузку QuickServe нужно
скопировать в `bulletins/<категория>/` и слить её `index.json` с общим
реестром, после чего прогнать конвейер заново.

Нужны пакеты: `beautifulsoup4`, `lxml`, `pymupdf`, `pillow`.

## Деплой на GitHub Pages

Статический сайт, сборка не нужна. GitHub Pages обслуживает файлы этой ветки
из корня репозитория; `.nojekyll` отключает обработку Jekyll (сайт — обычная
статика, Jekyll ему не нужен).

Настройка (один раз, в веб-интерфейсе GitHub): Settings → Pages → Source:
**Deploy from a branch** → Branch: **`gh-pages`**, папка `/ (root)`. После
сохранения сайт публикуется по адресу вида
`https://<owner>.github.io/Cummins_Parts_Book/` — GitHub переразвёртывает
его автоматически при каждом пуше в `gh-pages`.

Обновление сайта — пересобрать эту ветку из актуального состояния и запушить:
```
DROP="rawdata bulletins assets obsidian-vault fleet quickserve build fetch_raw.py" \
  build/make_deploy_branch.sh <исходная-ветка> gh-pages
git checkout gh-pages
git rm -r -q --cached api auth login.html middleware.js vercel.json
rm -rf api auth login.html middleware.js vercel.json
touch .nojekyll && git add .nojekyll
git commit -m "..." && git push -u origin gh-pages
```
`parts` намеренно не в `DROP`: фото деталей на этой ветке остаются локальными
для всех двигателей. Двигатели, у которых `data/<ESN>.js` ссылается на
`rawdata/<ESN>/parts` (свежесобранные), перед пушем нужно перегнать в
`parts/<ESN>/` и поправить поле `photos` на `parts/<ESN>` — иначе для них
после дропа `rawdata/` фото откатятся на CDN.

## Доступ

**У этой ветки нет входа по логину и паролю.** GitHub Pages — чисто
статический хостинг без выполнения серверного кода, поэтому серверная
проверка (Vercel Edge Middleware + `middleware.js` + `auth/`) здесь не
работает и намеренно убрана вместе с самими файлами `api/`, `auth/`,
`login.html`, `middleware.js`, `vercel.json`. Каталог на этом адресе виден
всем, у кого есть ссылка — обхода нет просто потому, что закрывать нечего.

Если нужен доступ по логину — используйте деплой на Vercel (ветка
`deploy-vercel`), где вход по-прежнему защищён `AUTH_SECRET` и
`auth/accounts.mjs` (`node build/make_user.mjs ...` — см. README той ветки).
